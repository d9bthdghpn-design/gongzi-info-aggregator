# 对公资讯标签体系 v5 —— 四维标签设计

> 版本：v5 ｜ 日期：2026-08-19 ｜ 适用：gongzi-info-aggregator（银行对公资讯聚合系统）

## 一、为什么重构标签体系

对现有 507 条资讯的数据审计发现三个核心问题：

1. **一级分类过粗**：`business_category` 仅 5 类（bid_action / fin_demand / account_chance / park_project / policy_ref），无法表达资讯重点。抽查显示：
   - `bid_action` 中混入大量低价值政府单一来源采购（如"海淀区委宣传部单一来源某活动"、"昌平区医院设备维修"）；
   - `policy_ref` 中混入展会、赛事、教材发布会等与银行业务弱相关的信息；
   - 402 条 policy 与 396 条 policy_ref 高度同构，分类无区分度。
2. **行业标签严重误标**：industry_tags 中 `finance` 高达 254 条（占 50%），根因是 AI 未配置 API Key 时模拟模式固定输出 `industry_tags: ["finance"]`；另有 `manufacturing/digital/energy/investment` 等非标准脏 code。
3. **商机信息不可检索**：客户经理无法按"补贴申报""土地出让""定增融资"等具体业务场景筛选资讯，情报价值未释放。

## 二、v5 标签体系总览（四维）

每则资讯自动标注：**1 个 action（一级行动）+ 1~3 个 topic（二级主题）+ 1~2 个 industry（行业）+ 1~2 个 area（区域）**。

| 维度 | 字段 | 数量 | 作用 |
|---|---|---|---|
| ① 行动分类 action | `business_category` | 5 | 判断"这条资讯对应什么银行机会"（一级导航/统计） |
| ② 主题标签 topic | `topic_tags`（新增） | 31 | 判断"资讯重点是什么"（二级细化/筛选项） |
| ③ 行业标签 industry | `industry_tags` | 15 | 判断"涉及什么行业赛道"（客户行业定位） |
| ④ 区域标签 area | `area_tags` | 9 | 判断"发生在哪个区域"（区域经营地图） |

### ① 行动分类 action（5 类，code 保持不变，兼容现有采集脚本/前端）

| code | 名称 | 判定要点 |
|---|---|---|
| bid_action | 招投标机会 | 采购/招标/磋商/比选/中标公告，主体为政府或企业 |
| fin_demand | 融资需求 | 定增、发债、并购、贷款、担保、上市辅导等融资信号 |
| account_chance | 开户结算机会 | 新设、注册、迁址、落户、跨境结算需求 |
| park_project | 区域产业动态 | 园区招商、平台落地、产业数据、重点项目 |
| policy_ref | 监管与政策 | 金融监管、财税政策、产业政策、行业规范 |

## 三、标签字典（TagDictionary）变更

| 变更 | 说明 |
|---|---|
| 新增 `topic` 类型 | 31 个主题标签（表②），带 keywords 供规则引擎使用 |
| 重建 `industry` 类型 | 16 类（表③），删除重复 medical/medical_health 合并为 medical_health，新增 government |
| 清理 `business` 类型 | 删除 v2 遗留 5 个（deposit/loan/investment_bank/treasury/supply_chain） |
| 保留 `action/area/info_type/opportunity` | action 5、area 扩为 9、info_type 4、opportunity 6 不变 |
| 字典总量 | 45 → 71 个标签 |

## 四、数据变更

```sql
ALTER TABLE news_items ADD COLUMN IF NOT EXISTS topic_tags jsonb DEFAULT '[]';
```

后端同步：`models/news.py`、`schemas/news.py` 增加 `topic_tags` 字段（JSON 数组）。

## 五、打标策略（规则引擎，无需 AI Key）

打标顺序（优先级从高到低）：
1. **action**：标题强词优先（开户 > 招投标 > 融资 > 园区 > 政策），正文补充，开户词仅看标题。
2. **topic**：31 个主题按关键词命中，且**限定在 action 对应组别**（保证主题与一级分类语义一致），取 1~3 个。
3. **industry**：16 个行业按关键词命中，取 1~2 个；无命中 → other（**不再默认 finance**）。
4. **area**：标题优先、正文补充；重点区 > 其他区县(other) > 全国 > 北京市级；"北京市"严格匹配避免"北京时间"误判。

> 后续若配置 AI API Key，可升级为 AI + 规则双通道：规则为骨架，AI 精修 business_tip 与评分。

## 六、预期效果

- policy_ref 396 条按主题拆分为 industry_planning / financial_regulation / subsidy_program 等细类，筛选项可直接定位"补贴申报窗口"；
- industry_tags 中 finance 254 条降至 112 条，真实行业（government 158 / medical_health 82 / education 73）显性化；
- bid_action 中低价值单一来源采购单独归入 single_source 主题，客户经理可一键过滤；
- area_tags 中 beijing 375 条（误标）降至 70 条，通州/亦庄/朝阳等区域显性化；
- 前端已支持：NewsCard 展示 topic 主题标签（紫色 chip），后端返回 topic_tags 即自动显示。
