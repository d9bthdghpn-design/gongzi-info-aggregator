## 二、采集架构简化（P0）

**原架构问题**：独立爬虫容器只跑单个爬虫就退出；Celery 采集任务是空壳；爬虫入库后不触发 AI。

**新架构**：
- 废弃独立 crawler 容器，Scrapy 在 Celery Worker 内通过 `CrawlerRunner` + `crochet` 执行
- Pipeline 改用 SQLAlchemy ORM 入库（不再用 psycopg2 裸 SQL），入库后自动触发 AI 处理
- 新增 RSS/Atom 爬虫（`rss_spider.py`），支持 feedparser 解析
- 配置化爬虫（`base_spider.py`）接通，从 `CrawlSource.selector_config` 读取选择器
- 去重 Pipeline 支持 Redis 不可用时降级为内存去重
- 默认数据库改为 SQLite（开发零依赖），生产用 PostgreSQL

**5 个 P0 数据源**（`init_db.py`）：
1. 中国政府采购网（ccgp.gov.cn）
2. 北京市政府采购网（ccgp-beijing.gov.cn）
3. 北京公共资源交易服务平台（ggzyfw.beijing.gov.cn，域名已更正）
4. 朝阳区政府（bjchy.gov.cn）
5. 北京市财政局（czj.beijing.gov.cn）

### base_spider 增强
- 标题提取：优先取链接的 `title` 属性，再取选择器文本，兼容`<font>`标签嵌套
- 日期提取：选择器取不到时用正则从列表项文本兜底，支持`2026-08-12 16:12`等格式
- 正文提取：支持逗号分隔多个备选选择器，BeautifulSoup兜底时移除`<script>/<style>`
- CleanPipeline 日期解析新增 `%Y-%m-%d %H:%M` 等带时间格式，正则提取纯日期

### 新增渠道：微信公众号（P1架构预留）
- 新增 `wechat_spider.py`：解析 `mp.weixin.qq.com/s/xxx` 文章页
- `crawl_type="wechat"`，文章URL存在 `selector_config.article_urls`（逗号分隔）
- 发现机制：MVP阶段手动提交URL，后续可接RSSHub/搜狗微信搜索
- init_db.py 预置"北京发布"、"朝阳发改"公众号源（默认未启用）

### 新增渠道：央国企官网（P1）
- init_db.py 预置国家电网、中国建筑集团、北京市国资委等源（默认未启用）
- 验证选择器后可一键启用，走通用 base_config 爬虫

### 反爬策略
- 礼貌采集：Chrome UA + 2秒随机延迟 + 随机UA中间件
- 不使用代理池对抗WAF，政府站反爬强度低
- 国密SSL站点（北京公共资源交易）预留Playwright浏览器渲染方案
